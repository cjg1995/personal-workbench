# 个人工作台技术方案

用户已确认 Electron + Vue 3 + TypeScript + Vite、宿主内置 SQLite 和当前用户 NSIS 安装。月报保留原截图位置为空白占位区，清除旧正文，增加月份姓名标题。

## 实测环境

Windows 10 x64，Node 22.20.0，Git 2.55.0。Electron 45.0.0 实测内置 Node 24.22.0、SQLite 3.53.4；中文读写、WAL 一致备份和隔离渲染通过。没有额外 SQLite 原生驱动，也不需要部署 Java/Web 后端服务来运行工作台。

Vue 3.5.44、TypeScript 5.9.3、Vite 8.3.5。Vue 编译进渲染包，作为开发依赖管理，不重复打包其 Node 模块。运行时 XML 使用 @xmldom/xmldom，ZIP/DOCX/APK 资源使用 fflate；不引入大型 UI 库、ORM、Shell 包装框架或云服务。

## 系统边界

渲染层仅调用明确的业务动作，sandbox/contextIsolation 开启，nodeIntegration 关闭；禁止导航、弹出任意窗口和浏览器权限请求。文件选择/另存为使用原生对话框。路径、进程和持久化在主进程服务中，Git 参数使用数组，说明使用 UTF-8 文件传递。

代码结构如下。

- src/core/submit.ts、git.ts：ERP/APP 检查、阶段、保护、恢复、stash 归属和真实推送核对。
- src/core/apk.ts：映射预检查、独立编译输出、资源同步、离线优先、签名/版本/内容校验和任务专属 APK。
- src/core/projects.ts：按原配置启动，真实就绪、外部实例检测、进程身份、停止与重开核验。
- src/main/service-runner.cjs：独立进程监督和脱敏日志，允许用户明确选择退出后保留自有服务。
- src/native/WorkbenchTomcat.java：使用原 Bootstrap、server.xml、上下文 XML、部署目录及 JRebel；先启动容器，再执行 IDEA 原本承担的指定上下文部署。配置仅在内存中加载，不重写既有配置。Java 8 字节码在安装包内，启动时提取到工作台自己的运行目录。
- src/shared/redact.cjs：命令执行与独立监督进程共同使用的日志过滤，覆盖私钥、密码、认证头、Cookie 和 URL 凭据等常见格式。
- src/core/records.ts、documents.ts：记录、逐物理行 TXT 导入、来源绑定的人工月报和基于现有模板的 Word 导出。
- src/core/review.ts：明确范围的只读差异、人工意见、已看状态及代码变化失效。
- src/core/store.ts、backup.ts、tasks.ts：SQLite 事务、一致快照、恢复保护、阶段历史和中断核实。
- src/main/main.ts：业务动作白名单与 Windows 集成；src/main/preload.cjs：受限通信接口。
- src/renderer/：固定导航、清爽列表与业务页面，不植入示例记录或模拟运行状态。

运行时 PowerShell 仅用于 Windows 只读进程、端口、窗口信息与 PEB 环境归属探测，不组织提交、合并、构建或项目启动流程。没有原业务 BAT/PowerShell 脚本依赖。Gradle、apksigner 与微信客户端使用原生 Java/Node 工具入口。开发依赖安装的 Electron 下载辅助使用系统下载和 ZIP 解压能力，按官方 SHA256 校验。

服务就绪需要工具的成功标记、HTTP 响应及本次进程树的监听归属共同成立。慢启动超时保留未知状态，重新检查可核实后来就绪的同一实例；未知而仍存活的自有进程不能重复启动。修改运行配置后，原实例须先停止。Git 预览指纹使用完整输出的流式摘要，超出完整输出上限的路径清单不能用于写操作。

H5/Vue 在确认就绪后通过系统浏览器打开实际地址；打开失败记录为部分失败，保留已经启动的服务。Tomcat 代理参数与生命周期实现参考 [JRebel 原生代理说明](https://manuals.jrebel.com/jrebel/advanced/launch-quick-start.html)和 [Tomcat Bootstrap API](https://tomcat.apache.org/tomcat-7.0-doc/api/org/apache/catalina/startup/Bootstrap.html)，并以本机真实启动结果核对。

原 Tomcat 的 HTTP 端口分别为 8080、8081，但关闭端口 8005 和 AJP 8009 重复。按计划逐项验证，不自动改写这些端口；同时运行遇到冲突时明确阻断，由用户在原配置处理。

## 数据和恢复

大目录预览完整保留文件清单，界面分批显示。审查正文单文件上限 512 KB、单快照合计 16 MB；超大工作区文件不读整份正文，按大小/时间核对变化，普通文本仍按实际内容核对。备份创建与恢复使用一致的容量上限，超限拒绝写入，避免生成不能恢复的包。

默认目录为 %LOCALAPPDATA%/PersonalWorkbench，安装目录不存业务记录。测试以 --data-dir 指向工作空间 .local/ 的独立目录。SQLite 使用 WAL 和事务；备份调用 SQLite backup API，TXT 快照按原字节保留。

恢复先校验 ZIP 清单、路径和 SHA256，再预览数量，原生确认后创建当前数据的保护备份。替换失败恢复原库和原快照；备份中的运行任务变为已中断，不自动重复写操作。APK、源码、业务工程和日志只作为路径引用。

APP 配置恢复保留每次 store/index.js 字节、原 Git 标志、原 index 和阶段日志。恢复 stash 冲突不反复 apply/pop，手动恢复配置前另存当前配置；人工在原工具处理后可记录确认再重新检查。
