## 当前状态

需求与 [全新 UI](../design/index.html)已整理，未开始应用开发。项目运行和人工审查都属于首版；不能沿用旧架构将其排到 V2。旧的内嵌 TAPD 导入、AI 入口、命令搜索和工具市场不在首版范围。

## 技术候选

原架构提出 Electron、Vue 3、TypeScript、Vite 和 SQLite，当前仍只是候选。桌面宿主、组件方案、SQLite 驱动及版本需要技术预研后确认。数据库驱动必须验证 Windows x64 安装包和宿主运行时的兼容性，不提前锁定某个原生依赖。

产品要求为 Windows 10/11 x64、本机单用户、安装更新保留数据；不需要另部署 Java 或 Web 后端服务器，不新增云账号或云同步。

## 实现边界

- 界面只调用明确的业务动作；文件访问、进程和持久化留在受控的系统能力层。若选 Electron，采用受限 Preload/IPC，不向渲染进程提供任意 Shell、文件覆盖或原始凭据接口。
- ERP/APP 提交和构建由工作台自身组织阶段、参数、保护与结果校验；不能直接或间接调用既有三个 BAT 或对应 PowerShell 业务脚本来冒充原生实现。
- Git、HBuilderX 编译器、Gradle、JDK、Android SDK 和现有签名配置是底层依赖，可继续复用；不得擅改分支策略、版本或签名。
- 项目启动按工作目录和配置判断归属，只停止工作台拥有的进程及其子进程；外部实例交由原工具管理。
- TAPD 首版仅启动现有客户端。Git 凭据继续用既有受信任机制，不放进普通设置、数据库或日志。

## 本地数据与历史

采用 SQLite 时，由受控服务操作数据库并使用事务。两类记录需要明确区分未来待办和已发生工作；业务发生日期与创建时间分开保存，导入无法确定日期时保留空值。

保存任务阶段、日志索引、产物关联、导入来源、月报草稿和审查快照。审查状态绑定实际差异；代码变化后失效。历史 APK 必须对应任务专属副本，不能指向后续会覆盖的固定输出。

首版使用手动备份和导入前快照，不把原架构中的定时备份建议当作新增需求。备份数据库时处理好事务及 WAL；恢复前保护现有数据，失败时可恢复。原 TXT 不回写、不删除。
