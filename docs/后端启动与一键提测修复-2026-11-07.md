# 0.1.44 后端启动与一键提测修复

## 后端启动

refsys 原来使用 `spring-boot:run`，编译完成后 Maven 与应用各保留一个 JVM。现在监督进程先执行 `compile dependency:build-classpath`，等待 Maven 成功退出，再通过原 JDK 直接运行 `com.ruoyi.RuoYiApplication`。应用 classpath 保留原项目的 `target/classes` 与运行依赖，包含 DevTools；JVM 参数直接作用于应用，Spring Profile 传给主类。编译或依赖解析失败不会继续启动应用。

homeproject、homeproject-ai 的实际配置均在一个 JVM 内运行 `WorkbenchTomcat`，其内部加载 Tomcat，不创建第二个 Java 进程。两者沿用 IDEA 的 `-Xms1024m -Xmx8192m` 与原 JRebel 代理，未发现 Maven 常驻问题，启动方式保持原样。

隔离 Spring Boot 工程使用了原 refsys 的 Codex/Cursor hook 脚本。两套 hook 均能编译并更新实际 HTTP 响应；DevTools 重启前后应用 PID 不变，编译完成后只留下一个应用 JVM。原项目 hook、POM 和业务代码未修改。

## 一键提测

Git 管理的一键提测纳入已暂存内容与全部已跟踪修改，包括同文件暂存后的后续修改、删除及已暂存新文件的后续修改。未跟踪新文件需要先暂存。APP/小程序的本地测试配置继续保护。普通 Commit 操作仍按 Git 暂存区提交。

后端仍使用独立 test 工作树，保留当前开发分支；固定分支项目仍在更新远程、恢复本地修改之后核对最终清单。预览使用完整本地差异，预览后工作区或暂存区变化仍要求重新检查。

提交说明、提交数量和确认按钮移到固定底栏，文件、差异与检查项在独立正文区域滚动。长列表及 1366×768、100%/125%/150% 缩放均验证通过。
