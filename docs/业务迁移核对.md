# 原生业务迁移核对

依据 PRD v1.1、2026-10-24 实际读取的三个业务脚本及 APP 自检用例。原脚本保持原位，仅为参考，不是应用运行依赖。本工作台不套用被管理项目的后端架构。

## ERP

1. 只读检查工作目录、origin、非空 feature-/hotfix- 后缀、开发 upstream、本地 test、origin/test、test upstream。
2. 定位占用 test 的 worktree；其他 test worktree 有已跟踪脏文件时停止。
3. 预览已有暂存内容及已跟踪未暂存文件；未暂存的未跟踪文件不纳入。
4. 执行前显示源目录、开发分支、test 工作目录、推送目标和提交范围。
5. 暂存已跟踪修改，必要时提交；确认已跟踪工作区干净，执行原有开发分支 push。
6. 切换到 test 或定位已占用 test 的工作目录，检查干净状态，pull --ff-only origin test，merge 开发分支，push test。
7. 保留最终分支，不自动切回。分别保存本地提交、开发推送、test 更新、合并和推送结果。
8. 命令边界响应停止；失败保留实际 Git 状态，不 reset、不强推、不自动中止合并。

ERP 的预览失效指纹核对分支、HEAD、暂存区和已跟踪差异；不对不纳入提交的未跟踪构建产物读取全文件正文。未跟踪项仍在跳过清单完整列出。外部暂存任何新文件会改变索引，使原预览失效；工作台不会因此自动加入其他新文件。

## APP

1. 四个仓库一次选一个，dev 固定；拒绝 detached HEAD、未完成 Git 操作、冲突、子模块及缺失的已跟踪 store/index.js。
2. fetch origin dev；检查 origin/dev..HEAD 是否修改受保护文件。
3. 保存 store 原始字节、assume-unchanged/skip-worktree、原 index 和恢复日志，逐阶段持久化。
4. 临时清除 store Git 标志，恢复该文件至 HEAD；其余本地修改含未跟踪文件保存到本次专属 stash。
5. merge --no-edit origin/dev；stash apply --index，仅成功时按哈希定位并删除本次 stash。
6. 成功、失败、取消均恢复 store 原始字节及标志。恢复冲突保留 stash，禁止自动再次 apply。
7. 按现有规则形成最终清单，恢复暂存区到 HEAD 后仅暂存允许文件；待用户确认说明。取消保留更新和本地恢复。
8. 有变更才 commit；无新变更可以 push 已有提交。推送前再检查受保护文件历史，push origin HEAD:refs/heads/dev，再 ls-remote 核实 HEAD。
9. 推送失败保留提交；重新检查后重试，不生成重复提交。重启后未核实任务标为中断，不能自动继续写操作。

### 文件规则

规则分别判断已跟踪与未跟踪文件，迁移原 PowerShell 正则的大小写行为。

- 始终排除 store/index.js。
- 排除隐藏目录、test/tests/__tests__/__mocks__/__snapshots__、node_modules、unpackage、dist、build、coverage、log/logs、tmp/temp。
- 排除 test-、test_、test. 命名，以及 .test/.spec 文件。
- 排除 .env、日志/临时/备份、压缩包、安装包、密钥和签名文件。
- 已跟踪其他文件可纳入，包含已跟踪 package.json。
- 新文件排除 md/txt/bat/ps1/sh/patch/diff，仅允许 api/components/js/lib/nativeplugins/pages/static/store/utils 下的源码，以及指定根文件。
- 根文件白名单为 App.vue/main.js/mixin.js/manifest.json/pages.json/uni.scss/icon.png|jpg|jpeg|webp。新 package.json 不自动纳入。
- 文件路径使用参数数组及 literal pathspec，提交说明用 UTF-8 文件传递，不拼接 Shell。

## APK

1. 从实际 manifest、Gradle、dcloud_control.xml、SDK 配置读取映射、包名、版本和工具；不硬编码示例版本。
2. 每任务独立资源输出；复用 HBuilderX Node/CLI、原 JDK/SDK/Gradle wrapper 和签名。
3. 检查必要资源、导出 AppID；仅同步本 APP 的 www；拒绝越界及链接目录，保持原生配置。
4. Gradle 离线优先；只对明确的离线依赖缓存缺失重试联网。
5. 逐文件核对导出、宿主和 APK 资源及大小写；验证签名、包名、版本，全部通过才成功。
6. 同 APP 锁定，停止仅作用本任务进程树。任务完成保留专属 APK 和 SHA256，历史不指向可覆盖输出。

## 验证边界

Git 成功、无变更、取消、冲突、推送拒绝、worktree、特殊路径、stash 归属及重启恢复先在工作空间内的临时仓库与 bare remote 验证。

真实仓库写入、远端分支变更、APK 宿主资源覆盖及可能访问既有业务数据的服务启动，必须在具体对象、操作和影响列明后取得用户确认。只读探测不得声称已完成真实集成验收。
