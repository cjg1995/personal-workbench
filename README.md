# 个人工作台

Windows 本地桌面应用，使用 Electron、Vue 3、TypeScript、Vite 和 Electron 内置 SQLite。源码、安装包和验收材料均在本工作空间。HomeProject、推荐官是被管理的既有项目，本目录不是它们的后端源码目录。

需求以 PRD v1.1 和用户后续决定为准；界面依据本目录 14 张新设计图实现。首次打开没有示例记录、虚构分支或模拟运行结果。

## 启动与安装

当前源码版本为 0.1.60。安装包为 `release/PersonalWorkbench-0.1.60-Setup.exe`，选择当前用户可写目录安装，不需要额外部署数据库或服务器。本机默认安装到 `%LOCALAPPDATA%\Programs\PersonalWorkbench\个人工作台.exe`；切换版本前先保存并退出已运行的工作台，旧运行目录暂留以继续管理其已经启动的后台服务。

「项目管理」保留项目运行操作，并新增独立 Monaco 代码编辑器。编辑器支持多文件、保存与外部冲突保护、项目搜索、跳转历史；Java 使用随安装包提供的 Eclipse JDT LS 做项目级语义导航、补全和诊断。功能、快捷键、验证结果及语言限制见 [代码编辑器交付记录](docs/代码编辑器-2026-11-12.md)。首次从源码打包会下载并校验固定版本的 Java 语言服务和运行时，后续使用本地缓存。

一键提测在更新前和最终确认时均可编辑提交说明，按项目保留草稿。右侧使用与独立 Git 对比相同的单页编辑器，Ctrl+S 保存；离焦、切换文件、关闭或离开页面时询问保存、不保存或继续编辑。待提交阶段保存会同步更新暂存内容与校验指纹。浅色差异沿用 IDEA 配色，修改行蓝色、段内新增文字绿色、整段新增绿色、删除灰色。

从源码运行，在本目录执行以下命令。开发使用 Node 22.20.0；首次安装依赖需要联网，Electron 下载按锁定版本和官方 SHA256 核验。

```powershell
npm ci
npm run build
npm start
```

常用开发命令：

```powershell
npm test
npm run verify:ui
node scripts/verify-git-client.cjs
node scripts/verify-diff-experience.cjs
npm run reinstall
node scripts/verify-workflows.cjs
node scripts/verify-referrer-submit.cjs
node scripts/verify-review-fixes.cjs
node scripts/verify-feedback.cjs
npm run package
```

`npm run reinstall` 会重新构建、打包，并静默覆盖安装到当前用户目录，改动后可直接打开已安装版本验证。

界面验收脚本使用本机已有的 Playwright，不是应用运行依赖；其他开发机需自行提供该测试工具。真实项目验收脚本会操作原工具链，先阅读下方验证边界。

`npm run build:tomcat` 只在修改 `src/native/WorkbenchTomcat.java` 后需要，使用 JDK 编译 Java 8 兼容组件；已核对的字节码随源码和安装包提供。工作台自身的记录、审查、月报不依赖 Java；运行或构建被管理的 Java/Android 项目需要其原有工具链。

## 使用与数据

首次使用先在“设置”核对实际工具、11 个项目路径和默认姓名。提交、打包先检查并预览，再由可见按钮启动；任务中心保存实际阶段。项目运行只停止拥有且创建时间、执行文件、实例标识均匹配的进程；外部实例交给原工具管理。端口冲突会阻断，不自动改端口。

“一键提测”位于 Git 管理工具栏，使用当前选中的项目，支持 ERP、APP、`refsys`、`refsys-ui` 和推荐官小程序。`refsys` 沿用 ERP 的 `feature-` / `hotfix-` 开发分支提交、推送及合并 `test` 流程，不自动创建 worktree，可沿用已存在的 `test` 工作目录；`refsys-ui` 仅允许在 `main` 提交并推送 `origin/main`；推荐官小程序仅允许在 `dev` 提交并推送 `origin/dev`。小程序根目录 `config.js` 与原 APP 的 `store/index.js` 使用相同的配置保护流程，更新前备份、排除暂存和提交、更新后恢复原始字节及 Git 标志，待推送历史含该配置修改时停止。前端在更新远程、恢复本地改动后确认最终提交清单。Git 管理的一键提测提交已暂存内容与已跟踪文件的全部本次修改，包含同一文件暂存后的后续修改；未跟踪的新文件需先暂存才纳入。搜索和显示筛选不改变提交范围，受保护配置始终排除。提交说明、待提交数量和确认按钮固定在弹窗底栏，正文独立滚动。

“Git 管理”用于人工 Git 操作；双击变更文件打开独立最大化对比窗口，工作区比较默认允许编辑与逐块操作，暂存区及历史版本比较保持只读。顶部 Commit 打开本地提交窗口，先暂存文件、填写说明后提交；一键提测在同一页打开预览并执行原自动化交付链。离开并返回 Git 管理时保留项目、内部页签、筛选、选择、提交说明和滚动位置。功能、测试证据及限制见 [Git 管理重构交付记录](docs/Git管理重构-2026-11-06.md)。
